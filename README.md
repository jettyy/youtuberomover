# silence_cut — 무음 자동컷

롱폼 유튜브 영상(화면 녹화 + 마이크)에서 말 사이의 무음 구간을 찾아 자동으로 잘라내고
`원본이름_cut.mp4` 로 저장합니다. 원본 파일은 수정하지 않습니다.
**창(GUI)에서 버튼으로 쓰는 방법**과 **명령어(CLI)로 쓰는 방법** 둘 다 지원합니다.

## 준비 (처음 한 번)

1. **Python 3.8 이상** — <https://www.python.org/downloads/>
   - 설치 화면에서 **"Add python.exe to PATH"** 체크, "tcl/tk and IDLE" 은 기본값(체크) 그대로 두기
2. **ffmpeg** — 명령 프롬프트에서 `winget install Gyan.FFmpeg` (또는 `choco install ffmpeg`)
   - 또는 <https://www.gyan.dev/ffmpeg/builds/> 에서 받아 `bin` 폴더를 PATH 에 추가
   - 새 터미널에서 `ffmpeg -version` 이 나오면 OK
3. (선택) 드래그&드롭을 쓰려면: `pip install tkinterdnd2`

## 창(GUI)으로 쓰기 — 추천

**`run_gui.bat` 을 더블클릭**하면 창이 뜹니다. (`silence_cut_gui.pyw` 를 직접 더블클릭해도 됩니다)

1. **[파일 추가]** / **[폴더 추가]** 로 영상을 넣습니다 (tkinterdnd2 설치 시 끌어다 놓기도 가능).
2. **컷 강도**를 고릅니다.
   - 자연스럽게: 0.8초 이상 쉼만 자르고 앞뒤 0.2초 여유
   - 기본: 0.5초 이상 쉼을 자르고 앞뒤 0.12초 여유
   - 빡빡하게: 0.35초 이상 쉼을 자르고 앞뒤 0.08초 여유
   - 세부 값(무음 기준 dB, 여유 등)을 직접 바꾸면 "직접 설정"으로 바뀝니다.
3. **[미리 분석]** 으로 얼마나 잘릴지 먼저 확인하거나, 바로 **[▶ 컷 시작]** 을 누릅니다.
4. 진행률과 로그가 창 아래에 표시되고, 끝나면 결과 폴더가 열립니다.
   **[■ 중지]** 를 누르면 즉시 멈추고 미완성 파일은 자동으로 정리됩니다.

**창이 안 뜰 때**
- zip 파일 안에서 바로 실행하지 말고, 먼저 **압축 풀기**를 한 뒤 풀린 폴더에서 실행하세요.
- `run_gui.bat` 이 오류를 보이면 그 창을 캡처해 두세요 (Python 설치 위치 진단 정보가 함께 나옵니다).
- 대신 명령 프롬프트에서 이 폴더로 이동해 `py silence_cut_gui.pyw` (또는 `python silence_cut_gui.pyw`) 로 실행할 수도 있습니다.
- 시작 중 오류가 나면 같은 폴더에 `silence_cut_error.log` 가 생깁니다.

설정 값은 자동 저장되어 다음 실행 때 그대로 유지됩니다 (`%USERPROFILE%\.silence_cut_gui.json`).

## 명령어(CLI)로 쓰기

```bat
:: 파일 하나 (출력: 영상_cut.mp4)
python silence_cut.py --input "D:\녹화\영상.mp4"

:: 출력 경로와 파라미터 지정
python silence_cut.py --input "영상.mp4" --output "영상_cut.mp4" --db -30 --min-silence 0.5 --padding 0.12

:: 폴더 안의 모든 mp4 일괄 처리 (이미 _cut 으로 끝나는 파일은 제외)
python silence_cut.py --input "D:\녹화 폴더"

:: 렌더링 없이 어디가 잘릴지만 미리 확인
python silence_cut.py --input "영상.mp4" --dry-run
```

한글·공백이 들어간 경로도 그대로 쓰면 됩니다 (따옴표로 감싸기).
ffmpeg 를 PATH 에 넣지 않았다면 `--ffmpeg "C:\ffmpeg\bin\ffmpeg.exe"` 로 직접 지정할 수 있습니다.

## 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--input`, `-i` | (필수) | mp4 파일 또는 폴더 |
| `--output`, `-o` | 원본 옆 `_cut.mp4` | 출력 파일 (폴더 입력이면 출력 폴더) |
| `--db` | `-30` | 이 음량(dB) 이하를 무음으로 판정 |
| `--min-silence` | `0.5` | 이보다 짧은 무음은 무시 (초) |
| `--max-silence` | `10` | 이 이상 긴 무음은 **자르지 않고 경고만** (초, `0` = 제한 없음) |
| `--padding` | `0.12` | 무음 앞뒤로 남겨 둘 여유 (초) |
| `--min-keep` | `0.1` | 컷 사이에 이보다 짧게 남는 조각은 같이 제거 (초) |
| `--audio-track` | `0` | 탐지·출력에 쓸 오디오 트랙 (OBS 멀티트랙일 때) |
| `--encoder` | `auto` | `auto` = GPU(NVIDIA→Intel→AMD) 자동 탐지 후 없으면 CPU / `cpu` / 인코더 이름 직접 지정 (`h264_nvenc`, `libx264` …) |
| `--quality` | `high` | `high` 고화질(원본과 구분 안 됨) / `max` 최고화질(용량 큼) / `match` 원본 용량 맞춤(움직이는 장면 화질 저하) |
| `--crf` | (없음) | 화질 값 직접 지정 (낮을수록 고화질, `--quality` 보다 우선) |
| `--preset` | 인코더별 | libx264 `medium`, nvenc `p5` 등. 빠르게: `fast` / `p3` |
| `--fps` | 자동 | 출력 프레임레이트 강제 (예: `60`, `30000/1001`) |
| `--dry-run` | | 렌더링 없이 결과 요약과 잘릴 구간만 출력 |
| `--save-edl` | | 렌더링하면서 편집 리스트도 json 으로 저장 |
| `--overwrite` | | 이미 있는 출력 파일 덮어쓰기 (기본은 건너뜀) |
| `--chunk-size` | `80` | 한 번에 렌더링할 구간 수 (보통 건드릴 필요 없음) |

```

  무음 탐지: 100.0%  (00:42:17.3 / 00:42:17.3)  95.1x
  원본 길이      : 00:42:17.3 (2537.3s)
  탐지된 무음    : 312개
  잘라낼 구간    : 298개
  [경고] 10초 이상 긴 무음 2개는 자르지 않았습니다 (수동 확인 권장):
         - 00:12:34.5 ~ 00:12:48.1 (13.6s)
         - 00:30:02.0 ~ 00:30:15.7 (13.7s)
  총 제거 시간   : 411.8s
  예상 최종 길이 : 00:35:25.5 (2125.5s)  -> 원본 대비 83.8% (-16.2%)
  인코더         : h264_nvenc
  렌더링 1/4: 100.0% ...
  합치기: 100.0% ...
  최종 길이      : 00:35:25.5 (2125.5s)  -> 원본 대비 83.8%
```

## 동작 방식

1. **무음 탐지**: `ffmpeg silencedetect=noise=<db>dB:d=<min-silence>` 로 오디오만 빠르게 분석합니다.
2. **컷 리스트**: 각 무음 `[시작, 끝]` 에서 `[시작+padding, 끝-padding]` 만 잘라냅니다.
   `max-silence` 이상인 무음은 건너뛰고 경고를 출력합니다. 겹치는 컷은 합치고, 모든 경계는
   **프레임 단위로 스냅**해서 컷이 수백 개여도 오디오/비디오 싱크가 밀리지 않습니다.
3. **렌더링**: 남길 구간들을 `trim/atrim + concat` 필터로 이어 붙입니다.
   - 오디오 조각마다 8ms 페이드 인/아웃을 넣어 컷 경계의 "틱" 팝 노이즈를 방지합니다.
   - 구간이 많으면 청크(기본 80개)로 나눠 렌더링한 뒤 concat demuxer 로 **재인코딩 없이** 합칩니다.
     청크 단계의 오디오는 무손실 PCM 이고, AAC 인코딩은 마지막에 한 번만 합니다.
   - 가변 프레임(VFR) 녹화본은 고정 프레임(CFR)으로 맞춰 출력합니다.
4. 작업용 임시 파일은 출력 폴더의 숨김 폴더(`.silence_cut_*`)에 만들고 끝나면 지웁니다.
   완성되기 전에는 `_cut.mp4` 가 생기지 않으므로 중간에 중단해도 깨진 파일이 남지 않습니다.

### 왜 재인코딩을 하나요?

`-c copy`(스트림 복사)는 키프레임 위치에서만 자를 수 있습니다. 화면 녹화는 키프레임 간격이
2~10초라서, 0.5초짜리 무음을 복사 방식으로 자르면 말이 잘리거나 중복되고 싱크가 틀어집니다.
그래서 비디오는 **원본과 같은 코덱·해상도·프레임레이트로 딱 한 번** 인코딩합니다.
NVIDIA/Intel/AMD GPU가 있으면 자동으로 하드웨어 인코더를 사용해 빠르게 처리합니다.

### 화질 (재인코딩 손실)

한 번 더 인코딩하므로 이론상 손실이 0은 아니지만, 기본값(`고화질`)은 육안으로 원본과
구분되지 않는 수준으로 맞춰져 있습니다. 대신 **파일 용량은 원본보다 커질 수 있습니다**
(유튜브는 업로드 후 어차피 다시 인코딩하므로 업로드용으로는 큰 파일이 유리합니다).

| 화질 설정 | 스크롤 텍스트 테스트 PSNR (높을수록 원본에 가까움) | 용량 (원본 대비) |
|---|---|---|
| 고화질 (기본) | 평균 58 dB / 최저 51 dB — 원본과 구분 불가 | 약 1.8배 |
| 원본 용량 맞춤 | 평균 37 dB / 최저 28 dB — 스크롤 시 글자 번짐·잔상 | 약 0.6배 |

화면 녹화는 정지 화면에서는 비트레이트가 거의 0이다가 스크롤·화면 전환 때 크게 튀기 때문에,
"원본 평균 비트레이트"에 맞추면 움직이는 장면이 뭉개집니다. 그래서 기본값을 화질 고정 방식으로 둡니다.
글자가 아주 많은 화면이라 조금이라도 번짐이 보이면 `최고화질`(`--quality max`)을 쓰세요.

## 튜닝 팁

- **말 끝이 잘린다** → `--padding 0.2` 처럼 늘리거나 `--db -35` 로 낮추기
- **숨소리·키보드 소리 때문에 무음이 안 잡힌다** → `--db -25` 로 올리기
- **너무 빡빡하게 잘린다** → `--min-silence 0.8` 로 짧은 쉼은 남기기
- 먼저 `--dry-run` 으로 잘리는 양을 확인한 뒤 본 렌더링을 돌리면 시간을 아낄 수 있습니다.
- 출력에는 `--audio-track` 으로 지정한 오디오 트랙 1개만 포함됩니다.
